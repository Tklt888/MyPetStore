# 后台商品列表设计

## 目的

先完成一个可运行、可理解的只读商品列表，让管理端真正走通 `Controller → Service → Mapper → MySQL → Thymeleaf`，为后续新增、编辑、上下架和补货打基础。

## 本阶段目标

- 展示商品 ID、SKU、名称、分类、价格、库存和状态。
- 支持按商品名称或 SKU 关键字查询。
- 支持按商品状态筛选。
- 使用 MyBatis-Plus 服务端分页，每页 10 条。
- 查询条件与页码通过 GET 参数传递，页面整页刷新，不使用 AJAX。

## 本阶段不做

- 新增、编辑、删除商品。
- 上下架、补货和版本冲突处理。
- 管理员登录与权限检查。
- 前端用户商城页面。

## 实现约束

- 保持五模块依赖方向：`admin-web → service → dao → model`。
- 密码继续通过 `DB_PASSWORD` 环境变量提供，不写入代码或 Git。
- 查询参数在服务端校验；页码小于 1 时归一为 1。
- 列表使用 Thymeleaf 服务端渲染，符合 PRD 的非 AJAX 要求。

## 方案比较

1. MyBatis-Plus 服务端分页：只查询当前页，符合课程技术栈和真实项目习惯，本阶段采用。
2. 查询全部数据后在页面分页：实现简单，但浪费资源，未采用。
3. 手写分页 SQL：控制力强，但重复代码多，不适合当前教学阶段，未采用。

## 页面与调用链

访问 `/admin/products` 后，由 `ProductController` 接收查询条件，调用 `ProductService`，再由 `ProductMapper` 联表查询商品和分类。Controller 将分页结果交给 `product/list.html`，页面显示筛选表单、商品表格、总记录数和上一页/下一页链接。

## 验收标准

- 本地数据库存在演示数据时，页面能显示商品记录。
- 关键字和状态筛选结果正确。
- 上一页、下一页保留筛选条件。
- Maven 全量构建及自动测试通过。
