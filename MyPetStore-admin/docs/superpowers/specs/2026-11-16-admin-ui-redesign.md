# MyPetStore 管理端 UI 统一改版方案

## 1. 设计依据

- 使用技能：`design-taste-frontend` 的 app screen 流程。
- 抽取方向：`framed-sheet`（Framed sheet），seed `313915887`。
- 产品类型：commerce / seller back office。
- 覆盖屏幕：home、list、detail，以及现有 form、login、error 状态。
- 技术边界：继续使用 Spring Boot、Spring MVC、Thymeleaf 和原生 CSS；不迁移前端框架，不改变现有 URL、表单字段、CSRF、权限和业务规则。

选择 `framed-sheet`，因为本系统是由商品、分类、订单和客户组成的中等密度运营后台，需要长时间浏览表格和执行行内操作。浅色 L 形框架能建立稳定导航，内嵌白色工作区能统一不同模块，同时避免常见的深色侧栏、渐变卡片和“AI 仪表盘”风格。

## 2. 产品数据与管理员任务

1. 商品：约 60 条，包含 SKU、分类、价格、库存、状态和排序。
2. 分类：两级树，管理员新增、编辑和安全删除分类。
3. 订单：包含订单号、用户、金额、状态、创建时间和商品快照。
4. 客户：普通客户账号及启用、禁用状态，不展示密码散列。
5. 使用者：商城管理员，主要在笔记本电脑上操作，偶尔使用平板或手机查看。
6. 高频任务：查询商品、编辑商品、补货、处理已支付订单、启停客户。
7. 风险任务：删除分类、上下架、发货和禁用账号，必须保持现有确认与 CSRF 保护。
8. 产品身份：MyPetStore 管理端、宠物零售数据、真实商品名称和教学订单。
9. 首页不能使用虚构增长率、销售曲线或访客数据，只呈现可从数据库计算的事实。
10. MyPetStore 专属核心元素：真实“运营待办队列”，汇总待发货订单、草稿商品、低库存商品和禁用客户，并直接进入对应列表。

## 3. 视觉方向

### 3.1 核心构图

- 页面外层为低饱和绿灰色 L 形框架。
- 左侧固定导航宽 228px，顶部栏高 48px，两者使用同一背景且没有分割阴影。
- 工作区为白色 sheet，距窗口右侧和底部 8px，圆角 16px，只有 1px 浅边线，无阴影。
- 工作区统一内边距 24px，模块间统一间距 24px。
- 桌面端内容使用完整可用宽度，不把表格压在页面左半边。

### 3.2 MyPetStore 的“脸”

- 框架底色从宠物与自然语义提取为低饱和绿灰 `#f3f7f5`，白色工作区保持中性。
- 主色使用深松绿 `#176b5b`，只用于品牌标记、当前导航细线、核心数据和一个主要操作。
- 品牌标记采用简洁的“宠物店挂牌”轮廓与 MyPetStore 文字组合，不使用彩色圆形图标。
- 商品、订单、客户使用数据库中的真实名称、编号和状态作为界面材料。
- 不添加装饰性宠物插画；后台的产品身份来自真实商品与运营待办，而不是背景图案。

## 4. 全局框架

### 4.1 左侧导航

- 顶部：MyPetStore 标记、产品名和“商城后台”范围说明。
- 主导航：首页、商品、分类、订单、客户。
- 当前项使用中性灰绿底色，不使用大面积品牌色。
- 底部显示当前管理员“商城管理员”，并提供安全退出。
- 导航链接在所有业务页面保持一致，不再让各页面自行放置零散“返回首页”“订单管理”链接。

### 4.2 顶部栏

- 左侧显示当前模块的面包屑或页面名称。
- 右侧只保留真实功能：管理员身份与退出入口。
- 不添加没有后端能力的通知铃铛、全局搜索或帮助按钮。

### 4.3 页面标题行

- 标题 22px/600，使用名词：“商品管理”“订单详情”，不使用欢迎语。
- 可选副标题只描述当前数据范围或最重要发现。
- 右侧最多一个主要操作和一个次要操作，例如“新增商品”。

## 5. 页面级方案

### 5.1 登录页

页面问题：管理员如何安全进入系统？

- 居中的窄登录面板，保留产品标记、账号、密码和登录按钮。
- 不使用插画、渐变或分屏宣传文案。
- 错误提示放在字段组上方，使用浅红背景和深红文字。
- 输入框始终显示真实 label；焦点环清晰，密码错误不会导致布局跳动。

### 5.2 首页

页面问题：今天最需要管理员处理什么？

- 第一块为“运营待办”，使用真实数据库统计：待发货订单、草稿商品、低库存商品、禁用客户。
- 每项为一条可点击任务，而不是四张带图标 KPI 卡；数字 24–28px，标签 14px。
- 第二块为模块入口：商品、分类、订单、客户，展示真实总数或一句当前状态。
- 已有商品总数继续使用真实 `productCount`；其余统计需要新增只读聚合查询后才显示。
- 不添加销售增长、访问量、趋势图等当前数据库无法证明的内容。

### 5.3 商品列表

页面问题：哪些商品需要查询、编辑、补货或调整状态？

- 标题行右侧为唯一主要操作“新增商品”。
- 筛选器保持一行：搜索、一级分类、二级分类、状态；窄屏折叠为“筛选”面板。
- 表格不再包裹厚重卡片；表头为 12px 灰色句式文本，无色块。
- 商品名称作为最宽身份列；SKU 使用 IBM Plex Mono。
- 价格、库存、排序右对齐并使用等宽数字。
- 状态改为浅色状态标签：已上架为浅绿，草稿为中性灰。
- 行尾操作按频率显示“编辑”“补货”，上下架作为状态操作；危险状态不使用整行红色。

### 5.4 分类管理

页面问题：当前两级分类结构是否清楚，哪里可以新增或编辑？

- 保持树形表格，不把每个分类做成卡片。
- 一级分类行使用较强字重和轻微底色，二级分类缩进 20px。
- 编码使用 IBM Plex Mono；排序数字右对齐。
- “新增一级分类”为标题行主要操作；一级行保留“新增子分类”。
- 删除是红色文字按钮，并继续使用现有确认与后端约束。

### 5.5 订单列表与详情

列表问题：哪些订单需要处理？详情问题：这笔订单是否具备发货条件？

- 列表顶部用下划线状态标签切换：全部、待支付、已支付、已发货、已完成、已取消。
- 搜索订单号和每页条数位于状态标签下的工具栏。
- 金额右对齐；订单号使用 IBM Plex Mono；状态使用单个浅色标签。
- “已支付”行的“查看详情”保持清晰，但不在列表直接发货。
- 详情页用对象头部展示订单号、状态、用户和金额，下面分为“收货信息”“支付信息”“商品快照”。
- 只有已支付订单显示一个主要操作“确认发货”；其他状态不留空按钮位。

### 5.6 客户管理

页面问题：哪些普通客户可被查询，账号当前是否可用？

- 筛选器保持用户名、状态和每页条数。
- 用户名为身份列，邮箱和手机号为次要灰色信息。
- 启用/禁用状态使用浅绿或中性灰标签，不用饱和色块。
- 行尾只有一个反向状态操作：启用或禁用。
- 不新增编辑资料、修改角色、删除或密码重置入口，保持当前安全边界。

### 5.7 表单、补货和错误页

- 表单 label 始终位于字段上方；字段高 40px，说明文字与字段关联。
- 表单内容宽 720–820px，不让短字段横跨整个屏幕。
- 保存使用近黑或深松绿填充按钮；取消为描边按钮。
- 补货页突出商品名、当前库存和增量输入，不显示绝对库存编辑。
- 400、404 页面保留完整 shell，错误只出现在工作区中，并提供返回对应列表的明确操作。

## 6. 响应式方案

### 桌面（≥1101px）

- 228px 左侧导航 + 48px 顶栏 + 内嵌工作 sheet。
- 表格完整展示，操作列固定在右侧。

### 平板（641–1100px）

- 侧栏折叠为 48px 顶栏和菜单按钮。
- 表格保留 4–5 个关键列，次要字段合并为单元格第二行。
- 筛选器允许两行，但保持统一 16px 间距。

### 手机（≤640px）

- 工作 sheet 变成全屏，外框消失。
- 采用顶部菜单或底部 5 项导航：首页、商品、分类、订单、客户。
- 表格变成两行列表项：第一行身份和关键值，第二行显示其余字段；字段不直接丢弃。
- 点击目标至少 44px；筛选器进入独立面板；页面不得横向滚动。

## 7. 状态与交互

- Hover：仅加强边线或文字，不使用浮起阴影。
- Focus：统一 2px 深松绿焦点环，键盘用户可见。
- Loading：保留最终布局，用静态灰色块占位，不使用渐变 shimmer。
- Empty：保留表头和容器，显示一句原因与清空筛选操作。
- Error：错误出现在失败模块内部；全局错误页仅用于请求级 400/404。
- 成功：使用页面顶部的安静通知条，PRG 后可见，不使用遮挡操作的 toast 动画。
- 危险操作继续使用浏览器确认或后续统一确认对话框，不改变现有权限和事务语义。
- 不做页面入场动画；只为按钮按压、菜单打开、行 hover 和焦点提供即时反馈，并尊重 `prefers-reduced-motion`。

## 8. 组件与文件结构

建议新增：

```text
templates/fragments/layout.html       全局 shell、导航、标题行
templates/fragments/components.html   状态标签、分页、通知、空状态
static/css/admin-tokens.css            颜色、字体、间距令牌
static/css/admin-shell.css             L 形框架与响应式导航
static/css/admin-components.css        表格、表单、按钮、状态
static/js/admin-shell.js               手机菜单与最小交互
static/fonts/                           本地 IBM Plex 字体
```

现有 Thymeleaf 页面改用 fragment 组合，删除各页面重复的内联 `<style>`。这一步是 UI 重构，不改变 Controller 路由和 Service 接口。

## 10. 本轮明确不做

- 不引入 Vue、React、Bootstrap 或新的前端构建系统。
- 不为了首页好看而虚构销量、增长率、访问量或图表。
- 不改变数据库表结构、订单状态机和权限模型。
- 不新增客户资料编辑、角色修改、删除或密码重置入口。
- 不用渐变、玻璃、发光、彩色图标卡、深色侧栏或大面积装饰插画。
