# 商品维护与补货验收清单

本清单用于验证管理端 `FR-A-03` 与 `FR-A-04`。先初始化课程提供的 `MyPetStore` 演示数据库，在本机终端通过 `DB_PASSWORD` 提供 MySQL 密码，再启动管理端。不要把真实数据库密码写入文档、命令截图或 Git 提交。

## 启动与登录

1. 在 `MyPetStore-admin` 目录执行 `./mvnw clean verify`。
2. 运行 `java -jar store-admin-web/target/store-admin-web-0.0.1-SNAPSHOT.jar`。
3. 访问 <http://localhost:8081/admin/products>，确认未登录时跳转到登录页。
4. 使用课程演示管理员登录，确认商品列表按数据库显示。

## 新增与字段校验

1. 点击“新增商品”，选择现有二级分类，使用未占用 SKU 创建库存为 0 的测试商品。
2. 回到列表确认商品状态为“草稿”，没有自动上架；数据库中的 `version` 为 0。
3. 分别尝试重复 SKU、一级分类 ID、价格 0、三位小数价格、负库存、负排序、外部 URL 和包含 `..` 的封面路径，确认请求被拒绝且没有新增记录。
4. 确认页面没有删除商品入口。

## 编辑与版本保护

1. 打开测试商品编辑页，记录 SKU、库存和版本。
2. 修改名称、价格、简介、描述、封面路径、二级分类或排序并保存。
3. 确认允许字段已更新，SKU 和库存保持不变，版本增加 1。
4. 在两个浏览器标签中打开同一商品编辑页；先保存标签 A，再保存标签 B，确认标签 B 提示“商品已发生变化，请刷新后重试”，且 A 的数据未被覆盖。

## 上下架

1. 对库存为 0 的测试商品执行上架，确认操作成功、状态为 `ON_SALE`、版本增加 1。
2. 执行下架，确认状态恢复为 `DRAFT`、版本再次增加 1，库存不变。
3. 在两个标签保留相同旧版本，先在一个标签改变状态，再从另一个标签提交旧状态操作，确认旧操作被拒绝。

## 增量补货

1. 打开补货页，确认只显示当前库存、增加数量和提交入口，没有“调整为指定库存”的输入框。
2. 输入正整数 3，提交后确认数据库库存按最新值增加 3，版本增加 1。
3. 尝试 0、负数、空值和会导致 `INT` 溢出的数量，确认库存与版本均不改变。
4. 在两个标签打开补货页，先提交一个标签，再提交另一个旧版本标签，确认第二次被拒绝，不会基于旧库存重复计算绝对目标值。

## 权限与安全

1. 退出登录后直接访问新增、编辑或补货地址，确认跳转登录页。
2. 确认新增、编辑、上下架和补货都是 POST 操作；缺少有效 CSRF 令牌时不能写库。
3. 触发业务错误时确认页面不显示 SQL、数据库约束名或 Java 堆栈。
