# 后台普通用户查询与启停设计

## 意图

完成实验指导书要求的用户管理能力，并实现 PRD `FR-A-07` 中普通用户管理部分。管理员可以查询 `CUSTOMER` 账号并启用或禁用，但不能借此修改密码、提升角色、操作管理员账号或展示未经计算的消费统计。

## 目标

- 按用户名包含匹配、`ENABLED`／`DISABLED` 状态筛选普通用户并分页。
- 默认按用户 ID 升序，展示账号、显示名称、联系方式、状态和注册时间。
- 仅允许在 `ENABLED` 与 `DISABLED` 之间显式切换，并在页面提交前确认。
- 后端按目标 ID、`CUSTOMER` 角色和当前状态做条件更新，重复启停不产生副作用。
- 非法参数返回 400、缺失用户返回 404、管理员账号等非 `CUSTOMER` 目标返回 403；并发状态变化返回安全业务提示。

## 非目标

- 不新增、删除用户，不修改用户名、显示名、邮箱、手机号或密码。
- 不提供角色修改或管理员账号启停入口。
- 不展示消费总额、订单数量等未由本阶段可靠计算的统计。
- 不实现商品相册管理；它是另一项独立选做功能。
- 不在管理端工程中伪造用户端会话失效。管理端只负责落库账号状态。仅在用户端请求时读取当前状态不足以保证“禁用期间没有请求、重新启用后旧 Session 仍失效”；用户端后续还需设计独立、持久的会话撤销代际或等价机制，不能直接复用会因普通资料修改而变化且只有秒级精度的 `updated_at`。

## 约束与业务规则

- 查询始终固定 `role = 'CUSTOMER'`，不能通过请求参数扩大为管理员。
- 用户名搜索去首尾空白，空值表示全部，最长 50 字符，使用包含匹配。输入中的 `%`、`_` 和 SQL 转义字符按普通文字匹配，不能改变查询语义。
- 状态只接受 `ENABLED`、`DISABLED`；空值或 `ALL` 表示全部。
- 页码缺省为 1，小于 1 的整数归一为 1；格式错误或溢出返回 400。`pageSize` 默认 10，只接受 1—50。
- 列表固定按 `id ASC`，不开放客户端排序字段。超过末页显示空结果，保留筛选和页大小并提供第一页、最后一页入口；零匹配提供清空筛选入口。
- 启停请求只提交目标状态；服务端不信任页面角色或当前状态。
- 状态更新 SQL 使用 `WHERE id = ? AND role = 'CUSTOMER' AND status = ?`，并只修改 `status`。在没有中间反向变更时，同一旧状态发出的同向并发请求最多一个成功；相反目标请求可能按数据库执行顺序依次成为合法迁移，本期不增加版本列阻止 ABA。
- 更新影响 0 行时重新读取：不存在返回 404；角色不是 `CUSTOMER` 视为不可管理；已经是目标状态提示当前状态且不写入；仍为其他状态表示并发变化，提示刷新。
- 所有写请求为 POST，经过管理员认证、管理员状态复核和 CSRF 防护。

## 方案比较

1. 只读列表后续再做启停：改动较小，但不能形成用户管理闭环，也无法验证禁用状态。未采用。
2. 查询与启停完整纵向闭环：模型、Mapper、Service、页面和测试共享角色与状态边界，完成后可直接做管理端验收。采用此方案。
3. 使用通用 `updateById`：代码较短，但可能接受客户端传来的角色、密码或其他字段，也不能原子地区分并发启停。未采用，使用显式条件 SQL。

## 分层设计

### 模型

- 增加 `CustomerListQuery`，规范化用户名、状态、页码和页大小。
- 增加 `CustomerListItem` 只读 DTO，使用显式字段投影读取 ID、用户名、显示名、邮箱、手机号、状态和创建时间，绝不查询或返回 `password_hash`；无需为列表扩充持久化实体。
- 增加 `CustomerStatusCommand`，只表达目标状态。

### Mapper

- `selectCustomerPage` 的数据查询与分页计数均固定 `role = 'CUSTOMER'`，支持用户名字面量包含匹配和状态组合筛选，按 `id ASC`；LIKE 参数使用绑定并显式转义。
- `selectRoleStatusById` 用于更新失败后的安全判定，不读取密码散列。
- `updateCustomerStatus` 只修改状态，并要求 ID、角色和旧状态同时匹配。

### Service

- 查询服务规范化参数并创建 MyBatis-Plus 分页对象。
- 状态服务校验目标状态，先根据目标推导唯一合法旧状态，再执行条件更新。
- 更新成功直接返回；失败后使用能观察数据库当前状态的读取，区分不存在、不可管理、已经处于目标状态和并发变化。复用既有 `selectRoleStatusById` 时须保证事务快照不会把并发提交隐藏为旧状态。
- 状态变更放在事务中，不修改购物车、订单或会话数据。

### Web

- `GET /admin/customers`：筛选、分页和普通用户列表。
- `POST /admin/customers/{id}/status`：成功或重复操作使用 PRG 返回列表；参数错误、不可管理和目标缺失分别保留 400、403、404 状态，不能统一吞成 302。
- 列表展示中文状态和联系方式；每行只提供与当前状态相反的操作。
- 表单带 CSRF，按钮提交前显示确认；页面不出现密码、角色、删除或资料编辑控件。
- 后台首页及现有管理页面增加“用户管理”入口。

## 错误处理

- 未知状态、超长搜索、非法页码或页大小返回 HTTP 400 安全页面。
- 目标不存在返回 404；管理员或其他非普通用户返回 403 和“该账号不可管理”，且不回显目标账号资料。
- 重复启停通过 PRG 返回“账号已经处于目标状态”，不执行 UPDATE，因此不改变 `updated_at` 或产生其他副作用；成功更新允许数据库按 DDL 自动刷新 `updated_at`。
- 未预期异常不输出 SQL、密码散列、约束名或堆栈。

## 测试与验收

- Mapper 契约测试锁定 `CUSTOMER` 角色过滤、用户名包含匹配、ID 升序及只更新状态的条件 SQL。
- Service 测试覆盖查询规范化、状态边界、成功启停、重复启停、缺失用户、管理员账号和并发变化。
- MVC 与模板测试覆盖空状态、筛选保留、分页边界、确认表单、CSRF、无密码/角色编辑入口和安全错误。
- Security 测试使用真实 `AdminPrincipal` 覆盖：未认证且携有效 CSRF 时跳转登录、已认证缺 CSRF 时 403、有效管理员携 CSRF 能进入处理器、已禁用管理员在处理器前被拦截且 Service 未调用。
- 全项目 `./mvnw clean verify` 必须通过。
- 真实数据库验收启停普通用户、重复操作和管理员账号保护；用两个连接执行同向并发启停，确认影响行数只有一次，并核对失败路径的状态及 `updated_at` 不变。时间戳夹具预置为早于当前秒，避免秒级精度造成假阴性。
- 用户端完成账号状态过滤和持久会话撤销机制后，再执行两条路径：禁用期间已有受保护请求被拒绝；登录后禁用期间不访问、重新启用后旧 Session 仍被拒绝且必须正常登录。本轮保持未验收，不以管理端单元测试代替。

## 完成标准

管理员能够从真实后台页面筛选普通用户并安全启停；任何请求都不能修改密码、角色、管理员账号或其他资料；重复和并发操作不产生额外副作用；现有登录、分类、商品和订单功能保持通过。
