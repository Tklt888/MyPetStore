# 分类管理验收清单

本清单用于验证管理端 `FR-A-02` 两级分类维护。执行前应已初始化 `MyPetStore` 演示数据库，并在当前终端通过 `DB_PASSWORD` 提供本机 MySQL 密码。不要在本文档、截图或 Git 提交中记录真实密码。

## 启动准备

1. 在 `MyPetStore-admin` 目录执行 `./mvnw clean verify`，确认构建成功且没有测试失败。
2. 在当前终端设置 `DB_PASSWORD`，运行 `java -jar store-admin-web/target/store-admin-web-0.0.1-SNAPSHOT.jar`。
3. 打开 <http://localhost:8081/>，使用演示管理员 `admin` 登录。
4. 从首页进入“分类管理”，确认地址为 <http://localhost:8081/admin/categories>。

## 列表与分页

- 确认犬类、猫类、水族、鸟类、爬宠按排序显示为一级分类。
- 确认每个一级分类下显示宠物和用品二级分类，并清晰标识父分类。
- 若一级分类超过 10 个，确认下一页只加载下一批一级分类，同时保留每个一级分类的完整二级子树。
- 输入格式错误的页码应显示 HTTP 400 参数错误页；超过末页应显示空状态并可返回有效页。

## 新增与校验

1. 新增一个临时一级分类，例如编码 `TEMP_GROUP`、名称“临时分类”、排序 `90`，确认创建成功。
2. 在该一级分类下新增二级分类，例如编码 `TEMP_CHILD`、名称“临时子类”、排序 `10`，确认父分类正确。
3. 尝试再次使用 `TEMP_GROUP` 编码，确认后端拒绝并提示编码已存在。
4. 尝试在同一父分类下新增同名“临时子类”，确认后端拒绝；不同一级分类下允许同名二级分类。
5. 输入空白编码、全角空格名称、超过长度的文本或负数排序，确认后端拒绝且数据库没有新增记录。
6. 通过篡改请求把现有二级分类作为 `parentId`，确认后端拒绝第三级分类。

## 编辑不可变字段

1. 编辑 `TEMP_CHILD`，确认页面只允许修改名称和排序。
2. 将名称改为“临时子类已修改”、排序改为 `20`，确认保存成功。
3. 确认编码仍为 `TEMP_CHILD`，父分类仍为“临时分类”。
4. 即使额外提交 `code` 或 `parentId` 参数，确认后端不修改这两个字段。

## 受限删除

1. 尝试删除仍包含 `TEMP_CHILD` 的 `TEMP_GROUP`，确认提示“存在子分类”且数据不变。
2. 尝试删除犬类下已被商品引用的二级分类，确认提示“已被商品引用”且商品和分类都不变。
3. 先删除无商品引用的 `TEMP_CHILD`，再删除已无子分类的 `TEMP_GROUP`，确认两次删除均成功。
4. 刷新页面，确认临时分类没有恢复，其他演示分类和商品未受影响。

## 权限与请求防护

- 退出管理端后直接访问 `/admin/categories`，应跳转到本端登录页。
- 未登录状态不能执行新增、编辑或删除。
- 删除使用 POST 和 CSRF 防护；直接 GET 删除地址不会改变数据，无 CSRF 的 POST 返回 HTTP 403。
- 页面显示的分类名称按文本转义，不执行输入中的 HTML 或脚本。

## 本阶段结论边界

完成上述项目即可证明管理端分类维护闭环可用。`AC-25` 中“新增二级分类后用户端可选、创建商品并上架后两端一致”的跨端证据暂不在本阶段生成；它将在用户端分类导航和管理端商品新增功能完成后，使用同一个数据库统一验证。
