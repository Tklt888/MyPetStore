# 后台客户管理验收清单

## 准备

- [ ] MySQL 8.x 已启动，数据库中同时存在普通客户和管理员账号。
- [ ] 只在终端设置 `DB_PASSWORD`，项目、截图和 Git 中不包含真实密码。
- [ ] 执行 `./mvnw clean verify`，确认全部自动化测试通过。
- [ ] 启动管理端并以有效管理员登录。

## 查询与分页

- [ ] 打开 `/admin/customers`，只显示角色为 `CUSTOMER` 的账号，不显示管理员。
- [ ] 用户名关键字前后空白会被忽略，状态可筛选已启用或已禁用。
- [ ] 分别搜索包含 `%`、`_` 和反斜杠的真实用户名，只按这些字符的字面含义匹配。
- [ ] 每页 1、10、20、50 条均可使用，翻页保留用户名、状态和页大小。
- [ ] 无结果时可清空筛选；超过最后一页时可前往有效页。
- [ ] 非法状态、超长关键字、错误或溢出的页码返回 400。

## 启用与禁用

- [ ] 已启用客户只显示“禁用”，已禁用客户只显示“启用”。
- [ ] 提交前有确认提示，表单包含 CSRF 令牌。
- [ ] 禁用客户仅修改 `store_user.status`，不修改用户名、密码散列、角色和资料。
- [ ] 对同一目标状态重复提交时，状态不变，`updated_at` 也不刷新。
- [ ] 构造管理员 ID 提交状态变更返回 403，管理员数据不变。
- [ ] 构造不存在的 ID 返回 404，非法目标状态返回 400。
- [ ] 两个连接同时提交同向状态变更时，最多一个条件 UPDATE 成功。

## 用户端联动（暂未完成）

- [ ] 客户被禁用后，已有用户端会话立即失效。
- [ ] 客户被重新启用后，禁用前的旧会话仍不能恢复使用。

> 最后两项需要用户端实现持久会话撤销或会话版本机制，并进行双应用真实验收；当前管理端状态功能不能替代该证据。
