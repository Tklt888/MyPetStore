# 后台订单管理验收清单

## 准备

- [ ] MySQL 8.x 已启动，并已导入课程提供的最新数据库脚本。
- [ ] 只在终端设置 `DB_PASSWORD`，项目文件、截图和 Git 中不包含真实密码。
- [ ] 执行 `./mvnw clean verify`，确认全部自动化测试通过。
- [ ] 启动管理端并以有效管理员登录。
- [ ] 用户端已有至少一笔包含多个商品明细的真实订单。

## 列表与筛选

- [ ] 打开 `/admin/orders`，列表按创建时间、ID 从新到旧显示。
- [ ] 输入完整订单号（前后带空格），能精确找到对应订单。
- [ ] 分别选择待支付、已支付、已发货、已完成和已取消，结果只包含对应状态。
- [ ] 订单号与状态组合筛选正确；无结果时显示空状态。
- [ ] 每页 10、20、50 条均可使用，翻页后保留订单号、状态和页大小。
- [ ] `page=0` 或负数回到第一页；格式错误或溢出返回安全的 400 页面。
- [ ] 超过最后一页时，可以直接返回第一页或最后一页。

## 详情与快照

- [ ] 详情显示订单号、所属用户、收货人、电话、地址、总额、状态和相关时间。
- [ ] 多个商品明细均显示成交时 SKU、名称、单价、数量和小计。
- [ ] 在商品管理中修改商品名称或价格后，订单详情中的历史快照保持不变。
- [ ] 待支付和已取消订单显示“未支付”，不显示支付宝、微信、银行卡等虚假渠道。
- [ ] 已支付、已发货和已完成订单显示固定方式 `MOCK` 与数据库中的成功凭证。

## 发货

- [ ] 只有 `PAID` 订单详情显示“确认发货”按钮。
- [ ] 待支付、已取消、已发货和已完成订单无法通过直接 POST 变更为已发货。
- [ ] 确认发货后，订单变为 `SHIPPED` 并保存首次 `shipped_at`。
- [ ] 发货不修改订单金额、商品明细、库存、支付方式、支付凭证和支付时间。
- [ ] 重复提交发货显示已经处理，状态和首次发货时间保持不变。

## 双应用验收

- [ ] 用户端完成模拟支付后，管理端重新查询显示 `PAID`。
- [ ] 管理端发货一次后，用户端和管理端重新查询均显示 `SHIPPED`。
- [ ] 两个请求并发发货时只有一个成功，首次发货时间没有被覆盖。

> 双应用项目尚未同时具备订单流程时，以上三项保持未勾选，不以 Mock 测试替代真实验收证据。
